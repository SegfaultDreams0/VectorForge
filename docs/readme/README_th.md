## ภาพรวม

Roblox เป็นสภาพแวดล้อมที่สะดวกสำหรับสร้างประสบการณ์แบบโต้ตอบ แต่ปัญหาทางคณิตศาสตร์บางประเภทต้องใช้เทคนิคเชิงตัวเลขเฉพาะทางมากขึ้น

VectorForge สำรวจวิธีนำเทคนิคเหล่านี้มาใช้งานใน Luau ผ่านชุดโมดูลคณิตศาสตร์ที่เป็นอิสระต่อกัน คลังโครงการยังมีชั้นงานวิจัยเชิงทดลองที่ครอบคลุมหัวข้อการคำนวณทางวิทยาศาสตร์ เช่น พลศาสตร์ของไหล วิธีไฟไนต์เอลิเมนต์ กลศาสตร์ควอนตัม แม่เหล็กไฟฟ้า กลศาสตร์ต่อเนื่อง กลศาสตร์วงโคจร และกระบวนการสุ่ม

โครงการครอบคลุมแนวคิดที่พบได้ทั่วไปในคณิตศาสตร์เชิงตัวเลข วิทยาการหุ่นยนต์ เรขาคณิตเชิงคำนวณ กลศาสตร์คลาสสิก ความน่าจะเป็น และการหาค่าเหมาะที่สุด

VectorForge ไม่ได้มุ่งแทนที่ API ที่มีอยู่ใน Roblox แต่เน้นการดำเนินการทางคณิตศาสตร์ที่เกินขอบเขตของการเขียนสคริปต์เกมทั่วไป

**เป้าหมายคือทำให้เทคนิคคณิตศาสตร์ขั้นสูงเข้าถึงได้ นำกลับมาใช้ซ้ำได้ และเปิดให้ทดลองภายใน Roblox**

## เริ่มต้นอย่างรวดเร็ว

### การติดตั้ง

คุณสามารถติดตั้ง VectorForge ด้วยตนเอง หรือใช้การกำหนดค่าโปรเจกต์ Rojo ที่ให้มาด้วย

**การติดตั้งด้วยตนเอง**

1. เปิด Roblox Studio
2. ไปที่ `ReplicatedStorage`
3. สร้างโฟลเดอร์ชื่อ `VectorForge`
4. คัดลอก ModuleScript จาก `src/VectorForge/` ไปยังโฟลเดอร์นั้น
5. สร้าง `ReplicatedStorage/VectorForgeShared` แล้วคัดลอก ModuleScript ของยูทิลิตีที่ใช้ร่วมกันไปไว้ภายใน
6. คงชื่อ ModuleScript และโครงสร้างโฟลเดอร์เดิมไว้

โครงสร้างใน Explorer ควรมีลักษณะดังนี้:

```text
ReplicatedStorage
└── VectorForge
    ├── LieGroupKinematics
    ├── SpectralLinearAlgebra
    ├── BayesianStateEstimation
    ├── DifferentialPathGeometry
    ├── AutomaticDifferentiation
    ├── RigidBodyDynamics
    ├── NumericalOptimization
    └── TrajectoryPlanning
```

### Rojo

VectorForge มีการกำหนดค่าโปรเจกต์ Rojo รวมอยู่ด้วย

ตรวจสอบว่า `default.project.json` แมป `src/VectorForge` ไปยัง `ReplicatedStorage/VectorForge` และแมป `VectorForgeShared/` ที่รากคลังโครงการไปยัง `ReplicatedStorage/VectorForgeShared` โปรดตรวจสอบไฟล์โปรเจกต์ก่อนใช้งานโดยอาศัยการแมปนี้

สร้างโปรเจกต์:

```bash
rojo build default.project.json -o VectorForge.rbxlx
```

[เอกสาร Rojo](https://rojo.space/)

### การใช้งานพื้นฐาน

หลังติดตั้งแล้ว ให้โหลดโมดูลด้วยฟังก์ชัน `require()` ของ Roblox

```lua
local ReplicatedStorage = game:GetService("ReplicatedStorage")

local VectorForge = ReplicatedStorage:WaitForChild("VectorForge")
local VectorForgeShared = ReplicatedStorage:WaitForChild("VectorForgeShared")

local SharedConstants = require(VectorForgeShared:WaitForChild("Constants"))
local Lie = require(VectorForge.LieGroupKinematics)
local LinearAlgebra = require(VectorForge.SpectralLinearAlgebra)
local StateEstimation = require(VectorForge.BayesianStateEstimation)
local PathGeometry = require(VectorForge.DifferentialPathGeometry)

local AutomaticDifferentiation =
    require(VectorForge.AutomaticDifferentiation)

local RigidBodyDynamics =
    require(VectorForge.RigidBodyDynamics)

local NumericalOptimization =
    require(VectorForge.NumericalOptimization)

local TrajectoryPlanning =
    require(VectorForge.TrajectoryPlanning)
```

แต่ละโมดูลมีความสามารถของตนเอง ดู [เอกสารอ้างอิง API](../../docs/API.md) สำหรับการดำเนินการ พารามิเตอร์ และค่าที่ส่งกลับที่มีให้ใช้งาน

## โมดูลหลัก

ปัจจุบัน VectorForge สำรวจโดเมนทางคณิตศาสตร์แปดด้าน

| โมดูล | โดเมนทางคณิตศาสตร์ | จุดเน้นหลัก |
|---|---|---|
| `LieGroupKinematics` | ทฤษฎี Lie | การหมุนและการแปลงวัตถุแข็ง |
| `SpectralLinearAlgebra` | พีชคณิตเชิงเส้น | การดำเนินการเมทริกซ์และตัวแก้เชิงตัวเลข |
| `BayesianStateEstimation` | ความน่าจะเป็น | การประมาณค่าสถานะและความไม่แน่นอน |
| `DifferentialPathGeometry` | เรขาคณิตเชิงอนุพันธ์ | เส้นโค้ง ความโค้ง และการวิเคราะห์เส้นทาง |
| `AutomaticDifferentiation` | แคลคูลัสเชิงตัวเลข | การส่งผ่านอนุพันธ์ |
| `RigidBodyDynamics` | กลศาสตร์คลาสสิก | แรง แรงบิด และการเคลื่อนที่ของวัตถุแข็ง |
| `NumericalOptimization` | การหาค่าเหมาะที่สุด | การหาค่าต่ำสุดเชิงตัวเลข |
| `TrajectoryPlanning` | การวางแผนการเคลื่อนที่ | การสร้างและประเมินวิถี |

### 1. LieGroupKinematics

**Lie Groups · ทฤษฎีการหมุน · จลนศาสตร์ของวัตถุแข็ง**

การแทนค่าทางคณิตศาสตร์สำหรับการหมุนและการแปลงวัตถุแข็งในปริภูมิสามมิติ

แนวคิดที่ศึกษา:

- พีชคณิตควอเทอร์เนียน
- การดำเนินการหมุน SO(3)
- การแปลงวัตถุแข็ง SE(3)
- แผนที่เลขชี้กำลังและลอการิทึม
- การประมาณค่าเชิงเส้นบนทรงกลม (SLERP)
- การประกอบและการหาอินเวอร์สของท่าทาง
- การแทนค่า Twist

**การประยุกต์ใช้ที่เป็นไปได้**

- แอนิเมชันแบบ Procedural
- การกำหนดทิศทางกล้องอย่างราบรื่น
- การเคลื่อนที่ที่ได้รับแรงบันดาลใจจากวิทยาการหุ่นยนต์
- การประมาณค่าท่าทางสามมิติ
- การจำลองเชิงปริภูมิ

### 2. SpectralLinearAlgebra

**พีชคณิตเชิงเส้นเชิงตัวเลข · การคำนวณเมทริกซ์**

วิธีเชิงตัวเลขสำหรับจัดการเมทริกซ์ แก้ระบบสมการเชิงเส้น และดำเนินการแยกตัวประกอบทางคณิตศาสตร์

แนวคิดที่ศึกษา:

- การคูณเมทริกซ์และการทรานสโพส
- การแยกตัวประกอบ LU
- การคำนวณดีเทอร์มิแนนต์
- การแยกตัวประกอบ Cholesky
- การแยกตัวประกอบ QR แบบ Householder
- การประมาณค่า eigenvalue ของเมทริกซ์สมมาตร
- วิธี Conjugate Gradient
- การประมาณค่าแบบกำลังสองน้อยที่สุด
- การแก้ระบบสมการเชิงเส้น

**การประยุกต์ใช้ที่เป็นไปได้**

- การจำลองเชิงตัวเลข
- การถดถอยพหุนาม
- การประมาณค่าพารามิเตอร์
- การหาค่าเหมาะที่สุดทางคณิตศาสตร์
- การสร้างแบบจำลองเชิงคำนวณ

### 3. BayesianStateEstimation

**การอนุมานแบบเบย์เซียน · ความน่าจะเป็น · การประมาณค่าสถานะ**

วิธีประมาณสถานะภายในของระบบพลวัต เมื่อข้อมูลสังเกตไม่สมบูรณ์หรือได้รับผลกระทบจากความไม่แน่นอน

แนวคิดที่ศึกษา:

- ตัวกรอง Kalman แบบขยาย (EKF)
- แบบจำลองการเปลี่ยนสถานะ
- แบบจำลองการวัด
- การส่งผ่าน covariance
- การประมาณ Jacobian เชิงตัวเลข
- การแก้ไขค่าการวัด
- การคำนวณ innovation
- การคัดกรองค่าการวัดทางสถิติ

**การประยุกต์ใช้ที่เป็นไปได้**

- การติดตามตำแหน่งวัตถุที่มีสัญญาณรบกวน
- การทำนายการเคลื่อนที่
- การจำลองเซนเซอร์
- การประมาณวิถี
- การสร้างแบบจำลองระบบพลวัต

### 4. DifferentialPathGeometry

**เรขาคณิตเชิงอนุพันธ์ · การวิเคราะห์เส้นโค้ง**

การวิเคราะห์ทางคณิตศาสตร์ของเส้นโค้งที่กำหนดด้วยพารามิเตอร์และคุณสมบัติเชิงเรขาคณิต

แนวคิดที่ศึกษา:

- การประมาณค่าเส้นโค้ง Hermite
- อนุพันธ์อันดับหนึ่งและอันดับสูง
- ความโค้งและความบิด
- การอินทิเกรตความยาวส่วนโค้งเชิงตัวเลข
- การกำหนดพารามิเตอร์ตามความยาวส่วนโค้ง
- กรอบ Frenet
- กรอบการขนานตามแนวโค้ง
- การประมาณจุดที่ใกล้ที่สุด
- การสร้างวิถีที่มี jerk ต่ำสุด

**การประยุกต์ใช้ที่เป็นไปได้**

- การสร้างเส้นทางแบบ Procedural
- วิถี NPC ที่ราบรื่น
- ระบบรางกล้อง
- การสร้างแบบจำลองวิถียานพาหนะ
- การวิเคราะห์การเคลื่อนที่สามมิติ

### 5. AutomaticDifferentiation

**การหาอนุพันธ์อัตโนมัติ · แคลคูลัสเชิงตัวเลข**

สำรวจการคำนวณอนุพันธ์ด้วยการส่งผ่านข้อมูลอนุพันธ์ผ่านการดำเนินการทางคณิตศาสตร์และนิพจน์การคำนวณที่รองรับ

แนวคิดที่ศึกษา:

- การส่งผ่านอนุพันธ์แบบ Forward mode
- การประเมินนิพจน์การคำนวณ
- การติดตามอนุพันธ์
- การวิเคราะห์ความไว

**การประยุกต์ใช้ที่เป็นไปได้**

- การหาค่าเหมาะที่สุดโดยใช้ gradient
- การปรับพารามิเตอร์ให้เข้ากับข้อมูล
- การวิเคราะห์ความไว
- การทดลองทางคณิตศาสตร์ที่หาอนุพันธ์ได้

### 6. RigidBodyDynamics

**กลศาสตร์คลาสสิก · การจำลองทางฟิสิกส์**

สำรวจคำอธิบายทางคณิตศาสตร์ของการเคลื่อนที่วัตถุแข็งภายใต้แรง แรงบิด และคุณสมบัติความเฉื่อย

แนวคิดที่ศึกษา:

- การเคลื่อนที่เชิงเส้นและเชิงมุม
- การแทนค่ามวลและความเฉื่อย
- ความสัมพันธ์ระหว่างแรงและแรงบิด
- วิวัฒนาการของสถานะวัตถุแข็ง
- พลศาสตร์การเลื่อนที่และการหมุน

**การประยุกต์ใช้ที่เป็นไปได้**

- การทดลองทางฟิสิกส์
- การสร้างแบบจำลองระบบกลไก
- การจำลองที่ได้รับแรงบันดาลใจจากวิทยาการหุ่นยนต์
- การวิเคราะห์การเคลื่อนที่

### 7. NumericalOptimization

**การหาค่าเหมาะที่สุดเชิงตัวเลข · การลดค่าซ้ำ**

สำรวจเทคนิคเชิงตัวเลขเพื่อค้นหาคำตอบที่ทำให้ฟังก์ชันวัตถุประสงค์มีค่าต่ำสุดภายใต้สมมติฐานและข้อจำกัดที่รองรับ

แนวคิดที่ศึกษา:

- การประเมินฟังก์ชันวัตถุประสงค์
- การอัปเดตพารามิเตอร์แบบวนซ้ำ
- แนวคิดการหาค่าเหมาะที่สุดโดยใช้ gradient
- เกณฑ์การลู่เข้า
- การหาค่าต่ำสุดเชิงตัวเลข

**การประยุกต์ใช้ที่เป็นไปได้**

- การประมาณค่าพารามิเตอร์
- การฟิตเส้นโค้ง
- การปรับเทียบทางคณิตศาสตร์
- การทดลองการหาค่าเหมาะที่สุด

### 8. TrajectoryPlanning

**การวางแผนการเคลื่อนที่ · การสร้างวิถี**

มุ่งเน้นการสร้างและประเมินเส้นทางหรือโปรไฟล์การเคลื่อนที่ตามเวลาระหว่างสถานะหรือเป้าหมายเชิงพื้นที่

แนวคิดที่ศึกษา:

- การสร้างวิถี

## ส่วนขยายทางวิทยาศาสตร์

คลังโครงการมีชั้นส่วนขยายเชิงทดลองแยกต่างหากควบคู่กับโมดูลหลักเดิมทั้งแปด ส่วนเพิ่มเติมเหล่านี้จัดเรียงตามสาขาวิทยาศาสตร์ที่รากของคลังโครงการ และไม่ได้อยู่ภายใน `src/VectorForge/` ดังนั้นไลบรารีหลักเดิมจึงยังแยกจากโมดูลวิจัยที่กว้างขึ้น

แพ็กเกจส่วนขยายปัจจุบันประกอบด้วย:

- **โฟลเดอร์สาขาวิทยาศาสตร์ 15 โฟลเดอร์**
- **โมดูลตามสาขา 300 โมดูล** โดยมี 20 โมดูลในแต่ละสาขา
- **โมดูลสนับสนุนตามสาขา 30 โมดูล** โดยมีไฟล์เพิ่มเติมสองไฟล์ที่รากของแต่ละโฟลเดอร์
- **โมดูลยูทิลิตีที่ใช้ร่วมกัน 7 โมดูล** ใน `VectorForgeShared/`
- **ตัวอย่างการจำลองที่มีชื่อเฉพาะ 10 ตัวอย่าง**
- **ตัวอย่างค่าคงสภาพเชิงตัวเลขและการตรวจสอบ 10 ตัวอย่าง**

แพ็กเกจส่วนขยายมีไฟล์ Lua ทั้งหมด **357 ไฟล์** โดยไม่รวม README นี้ นี่เป็นเพียงจำนวนไฟล์ในคลังโครงการ ไม่ได้หมายความว่าทุกโมดูลเป็นตัวแก้ปัญหาทางวิทยาศาสตร์ที่ผ่านการตรวจสอบครบถ้วน

### สาขาวิทยาศาสตร์

| โฟลเดอร์สาขา | หัวข้อวิจัยหลัก |
|---|---|

| `control-systems/` | แบบจำลอง state-space การควบคุมป้อนกลับ ตัวสังเกต และการวิเคราะห์เสถียรภาพ |
| `finite-element-methods/` | การกำหนดรูปแบบเอลิเมนต์ ข้อมูลวัสดุ ควอดราเจอร์ และแนวคิดการประกอบ |
| `signal-processing/` | การแปลงแบบไม่ต่อเนื่อง การกรอง คอนโวลูชัน และทฤษฎีการสุ่มตัวอย่าง |
| `tensor-calculus/` | การจัดเก็บเทนเซอร์ การหดดัชนี เมตริก และการดำเนินการเชิงอนุพันธ์ |
| `differential-equations/` | การอินทิเกรตค่าเริ่มต้น ปัญหาค่าขอบเขต และการก้าวเชิงตัวเลข |
| `computational-geometry/` | เส้นโค้งพาราเมตริก ความโค้ง เพรดิเคตเชิงเรขาคณิต และแนวคิดเมช |
| `optimization-methods/` | วิธี gradient การค้นหาเส้น ฟังก์ชันวัตถุประสงค์กำลังสองน้อยที่สุด และกฎการหยุด |
| `quantum-mechanics/` | การแทนค่าฟังก์ชันคลื่น ความหนาแน่นความน่าจะเป็น และพื้นฐานแบบจำลองควอนตัม |
| `thermodynamics/` | สมการสถานะ คุณสมบัติทางความร้อน พลังงาน และการแปลงทางอุณหพลศาสตร์ |
| `electromagnetics/` | สนามแม่เหล็กไฟฟ้า แรงลอเรนซ์ ค่าคงที่ และการสุ่มตัวอย่างสนาม |
| `orbital-mechanics/` | การเคลื่อนที่ของวัตถุสองชิ้น พารามิเตอร์วงโคจร และค่าคงที่ทางกลศาสตร์ดาราศาสตร์ |
| `rigid-body-physics/` | ความเฉื่อย โมเมนตัมเชิงมุม การตั้งค่าการสัมผัส และพลศาสตร์การหมุน |
| `continuum-mechanics/` | มาตรวัดความเครียด ข้อมูลวัสดุยืดหยุ่น และพื้นฐานแบบจำลองเชิงองค์ประกอบ |
| `stochastic-processes/` | กระบวนการสุ่ม การก้าวแบบสุ่ม และการแจกแจงความน่าจะเป็น |

### โครงสร้างโฟลเดอร์

แต่ละสาขาวิทยาศาสตร์มีโฟลเดอร์ย่อยสามโฟลเดอร์:

- `analysis/` — โมดูลและการคำนวณที่มุ่งเน้นการวิเคราะห์
- `models/` — การแทนค่าแบบจำลองและสถานะ
- `solvers/` — ขั้นตอนเชิงตัวเลขและโมดูลที่เกี่ยวกับตัวแก้ปัญหา

แต่ละโฟลเดอร์สาขายังมีโมดูลสนับสนุนอีกสองโมดูลอยู่ที่รากโดยตรง ซึ่งให้การกำหนดค่าเฉพาะสาขา ข้อมูลวัสดุ ค่าคงที่ กฎการสุ่มตัวอย่าง หรือฟังก์ชันช่วยเหลือ

ยูทิลิตีที่ใช้ร่วมกันอยู่ในโฟลเดอร์รากเพียงแห่งเดียวชื่อ `VectorForgeShared/` ใน Roblox Studio โฟลเดอร์นี้ควรอยู่ภายใต้ `ReplicatedStorage/VectorForgeShared`:

| โมดูล | หน้าที่ |
|---|---|
| `Constants.lua` | ค่าคงที่ทางฟิสิกส์และคณิตศาสตร์ที่ใช้ร่วมกัน |
| `CoreRegistry.lua` | การลงทะเบียนและค้นหาโมดูลหลัก VectorForge ที่มีอยู่แบบชัดเจน |
| `EquationCatalog.lua` | แค็ตตาล็อกสมการกำกับแบบย่อเพื่อใช้อ้างอิง |
| `LinearAlgebra.lua` | การดำเนินการเมทริกซ์พื้นฐานบนอาร์เรย์แถว |
| `NumericalGuards.lua` | การตรวจสอบค่าจำกัด การจำกัดช่วง และการหารอย่างปลอดภัย |
| `NumericalKernels.lua` | เคอร์เนลเชิงตัวเลขระดับต่ำที่ใช้ร่วมกัน |
| `SimulationClock.lua` | การจับเวลาจำลองแบบช่วงเวลาคงที่ |

### การผสานรวมกับโมดูลหลัก

โมดูลส่วนขยายถูกเก็บแยกจาก `src/VectorForge/` โดย `VectorForgeShared/CoreRegistry.lua` มีกลไก dependency injection เพื่อให้สคริปต์ bootstrap สามารถลงทะเบียนอินสแตนซ์ของโมดูลหลักที่มีอยู่จริง

Registry จะไม่คาดเดาเส้นทางโมดูลหรือโหลดโมดูลหลักโดยอัตโนมัติ ให้ลงทะเบียนเฉพาะโมดูลที่มีอยู่จริงในโครงการและตรวจสอบ public API แล้วเท่านั้น

**สำคัญ:** ใช้โฟลเดอร์ที่ใช้ร่วมกันเพียงโฟลเดอร์เดียวชื่อ `VectorForgeShared` อย่าเก็บสำเนาคู่ขนานไว้ภายใต้ `shared`, `Shared` และ `VectorForgeShared` โมดูลของแต่ละสาขาและสคริปต์ bootstrap ควรอ้างถึงอินสแตนซ์ `ReplicatedStorage/VectorForgeShared` เดียวกัน

ตัวอย่าง:

```lua
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local Shared = ReplicatedStorage:WaitForChild("VectorForgeShared")
local CoreRegistry = require(Shared:WaitForChild("CoreRegistry"))

CoreRegistry.Configure({
    SpectralLinearAlgebra = require(path.to.src.VectorForge.SpectralLinearAlgebra),
    AutomaticDifferentiation = require(path.to.src.VectorForge.AutomaticDifferentiation),
    BayesianStateEstimation = require(path.to.src.VectorForge.BayesianStateEstimation),
})

local LinearAlgebraCore = CoreRegistry.Require("SpectralLinearAlgebra")
```

ซอร์สของส่วนขยายแทนสถานะทางคณิตศาสตร์ด้วยอาร์เรย์ตัวเลข และไม่ได้พึ่งพาชนิดข้อมูลเชิงพื้นที่ของ Roblox โดยตรง อย่างไรก็ตาม นี่ไม่ได้หมายความว่าทุกอัลกอริทึมเป็นตัวแก้ปัญหาฟิสิกส์ที่สมบูรณ์ หรือทุกโมดูลผ่านการตรวจสอบกับ implementation อ้างอิงแล้ว

### ตัวอย่างและไฟล์ตรวจสอบความถูกต้อง

โฟลเดอร์ `examples/` มีการศึกษาตัวเลขที่ตั้งชื่อแยกกัน เช่น การตอบสนองของออสซิลเลเตอร์แบบหน่วง การวิวัฒน์ของสถานะที่เชื่อมโยงกัน การตอบสนองไม่เชิงเส้น การลดลงของพลังงาน เสถียรภาพของการอินทิเกรต และวิวัฒน์ของสถานะในช่วงเวลายาว

ส่วนเพิ่มเติมใน `tests/` มีการตรวจสอบค่าคงสภาพเชิงตัวเลขขนาดเล็ก ซึ่งเป็นจุดเริ่มต้นที่มีประโยชน์สำหรับ regression test แต่ไม่สามารถใช้แทน benchmark เชิงวิเคราะห์ การตรวจสอบมิติ การศึกษาการลู่เข้า หรือการตรวจสอบกับข้อมูลวิทยาศาสตร์ที่เชื่อถือได้

### สถานะการวิจัยและการใช้งานจริง

ส่วนขยายทางวิทยาศาสตร์เป็นโครงสร้างพื้นฐานสำหรับการวิจัยเชิงทดลอง บางโมดูลเปิดเผยรูทีนเชิงตัวเลขที่นำกลับมาใช้ซ้ำได้และการคำนวณเฉพาะสาขา ส่วนโมดูลอื่นยังต้องกำหนดการทำให้ไม่ต่อเนื่องตามปัญหา เงื่อนไขขอบเขต กฎเชิงองค์ประกอบ หน่วย และกลยุทธ์ตัวแก้ปัญหา

ก่อนใช้ส่วนขยายในประสบการณ์ที่ใช้งานจริง:

1. ตรวจสอบอินพุต เอาต์พุต มิติ และหน่วยของโมดูล
2. ตรวจสอบสมมติฐานและเงื่อนไขขอบเขต
3. เปรียบเทียบผลลัพธ์กับคำตอบเชิงวิเคราะห์หรือข้อมูลอ้างอิงที่เชื่อถือได้
4. ทดสอบการลู่เข้าและเสถียรภาพเชิงตัวเลขในช่วงอินพุตที่เป็นตัวแทน
5. วิเคราะห์ต้นทุนการทำงานใน Roblox Studio
6. ตรวจสอบการผสานรวมโมดูลหลักกับ public API ที่มีอยู่จริง

ส่วนเพิ่มเติมเหล่านี้ขยายขอบเขตการวิจัยของคลังโครงการ แต่ไม่ได้เปลี่ยนขั้นตอนติดตั้งโมดูลหลักแปดโมดูลเดิม

## VectorForge ทำงานอย่างไร

VectorForge มีชุดโมดูลคณิตศาสตร์อิสระที่ใช้ภายในประสบการณ์ Roblox ได้ คุณกำหนดปัญหาหรือแบบจำลองทางคณิตศาสตร์ เลือกโมดูลที่เกี่ยวข้อง ป้อนข้อมูลที่ต้องการ และใช้ผลลัพธ์ที่ส่งกลับในระบบของคุณ

แผนภาพด้านล่างแสดงภาพรวมของเวิร์กโฟลว์นี้ เป็นคำอธิบายเชิงแนวคิดเกี่ยวกับวิธีที่นักพัฒนาใช้ไลบรารี ไม่ได้หมายความว่าโมดูลทั้งหมดเชื่อมต่ออัตโนมัติหรือ VectorForge ทำงานเป็น pipeline แบบตายตัวเพียงชุดเดียว

| ห้องทดลองเสถียรภาพเชิงตัวเลข | เปรียบเทียบแนวทางการบวกเชิงตัวเลข |

การทดลองเหล่านี้มีไว้เพื่อการสำรวจ ไม่ใช่การจำลองที่พร้อมใช้งานจริง

ตัวอย่างบางส่วนใช้การคำนวณอ้างอิงแบบย่อหรือตัวแปลงภาพแสดงผล ตัวอย่างกลศาสตร์ท้องฟ้าและวงโคจรใช้แบบจำลองนิวตันแบบย่อ ไม่ใช่ทฤษฎีสัมพัทธภาพทั่วไป ส่วนภาพแสดงผล Kalman เป็นการสาธิตการปรับเรียบแบบง่าย ไม่ใช่การติดตั้ง EKF ที่สมบูรณ์

ดู [experiments/README.md](../../experiments/README.md)


<a id="simulations"></a>
## การจำลอง

โฟลเดอร์ `simulations/` เก็บแบบจำลองเชิงตัวเลขแบบแยกเดี่ยวไว้สองสามรายการ มีประโยชน์สำหรับทดสอบการเปลี่ยนแปลงของระบบตามเวลาโดยไม่ผูกการคำนวณเข้ากับฉาก Roblox

สคริปต์ปัจจุบันครอบคลุมปัญหาสองประเภท:

| สคริปต์ | สิ่งที่จำลอง |
|---|---|
| `TwoBodyOrbit.lua` | การเคลื่อนที่สัมพัทธ์ภายใต้แบบจำลองแรงโน้มถ่วงนิวตันแบบย่อ |
| `DampedOscillator.lua` | มวลที่ติดกับสปริงซึ่งมีแรงหน่วงเชิงเส้น |

ทั้งสองใช้ขั้นตอน Runge–Kutta อันดับสี่ ผู้เรียกเป็นผู้กำหนดสถานะเริ่มต้นและช่วงเวลา ดังนั้นนาฬิกาการจำลองและเงื่อนไขหยุดจึงอยู่ภายใต้การควบคุมของผู้เรียก

ตัวอย่างวงโคจรใช้หน่วย SI ได้แก่ เมตร เมตรต่อวินาที วินาที และพารามิเตอร์แรงโน้มถ่วงหน่วยลูกบาศก์เมตรต่อวินาทีกำลังสอง ส่วนออสซิลเลเตอร์ใช้เมตร กิโลกรัม วินาที นิวตันต่อเมตร และนิวตัน-วินาทีต่อเมตร

โมเดลเหล่านี้ตั้งใจให้มีขนาดเล็ก สคริปต์วงโคจรไม่คำนึงถึงวัตถุท้องฟ้าอื่น แรงต้านบรรยากาศ การชน หรือผลเชิงสัมพัทธภาพ ออสซิลเลเตอร์สมมติว่าสปริงเป็นเชิงเส้นและมีแรงหน่วงหนืดเชิงเส้น ไม่ควรถือว่าโมเดลใดเป็นเอนจินฟิสิกส์สำหรับใช้งานจริง

ดู [simulations/README.md](../../simulations/README.md) สำหรับการตั้งค่า พารามิเตอร์ และข้อจำกัดของแต่ละสคริปต์

<a id="datasets"></a>
## ชุดข้อมูล

โฟลเดอร์ `datasets/` เก็บค่าอ้างอิงและข้อมูลตัวอย่างที่สคริปต์และการทดลองของโครงการใช้ การแยกข้อมูลออกจากอัลกอริทึมช่วยให้นำอินพุตเดิมกลับมาใช้ซ้ำได้ง่าย และเห็นชัดเจนว่าการสาธิตกำลังใช้ข้อมูลใด

| ไฟล์ | เนื้อหา |
|---|---|
| `PhysicalConstants.lua` | ชุดค่าคงที่ทางฟิสิกส์ขนาดเล็กในหน่วย SI |
| `SolarSystem.lua` | มวลโดยประมาณ กึ่งแกนเอกเฉลี่ย คาบการโคจร และพารามิเตอร์แรงโน้มถ่วงที่คำนวณได้ของดาวเคราะห์บางดวง |
| `MotionSamples.lua` | ลำดับสั้น ๆ ของการสังเกตตำแหน่ง 2D สังเคราะห์ที่มี timestamp |

ค่าของดาวเคราะห์เป็นข้อมูลอ้างอิงที่ผ่านการปัดเศษ ไม่ใช่ปฏิทินดาราศาสตร์ความแม่นยำสูง ตัวอย่างการเคลื่อนที่เป็นข้อมูลที่สร้างขึ้น ไม่ใช่การวัดจากเซนเซอร์จริง ความแตกต่างนี้สำคัญเมื่อใช้ในการเปรียบเทียบเชิงตัวเลขหรือการทดลองประมาณค่าสถานะ

เมื่อเพิ่มข้อมูล ให้ระบุหน่วยและบอกว่าเป็นค่าที่วัดได้ ข้อมูลสังเคราะห์ หรือค่าโดยประมาณ จะช่วยลดความสับสนภายหลัง

ดู [datasets/README.md](../../datasets/README.md) สำหรับข้อกำหนดข้อมูลและตัวอย่างการใช้งาน

<a id="visualizations"></a>
## ภาพแสดงผล

โฟลเดอร์ `visualizations/` มีตัวช่วย Roblox ขนาดเล็กสำหรับแสดงผลการคำนวณในฉาก 3D แนวคิดคือแยกคณิตศาสตร์ออกจากการวาดภาพ: การจำลองหรืออัลกอริทึมสร้างค่า แล้ว renderer แปลงค่าเหล่านั้นให้เป็นสิ่งที่ตรวจสอบได้

| โมดูล | สิ่งที่แสดง |
|---|---|
| `TrajectoryRenderer.lua` | ชุดจุด `Vector3` ที่เชื่อมต่อกันด้วยเซกเมนต์ที่ยึดตรึง |
| `VectorFieldRenderer.lua` | ตัวอย่างเวกเตอร์ที่แสดงเป็นตัวบ่งชี้ทิศทางในพื้นที่ 3D |

ทั้งสองโมดูลสร้าง `Model` ไว้ใต้ parent ที่คุณระบุ ชิ้นส่วนต่าง ๆ ถูกยึดตรึงและไม่ชนกัน เมื่อแสดงผลเสร็จแล้ว ให้ทำลายโมเดลที่ส่งกลับมาเพื่อกำจัด instance ที่สร้างขึ้น

ตัวช่วยเหล่านี้เหมาะกับการดีบักและการสาธิตขนาดเล็ก ไม่ใช่การพล็อตทางวิทยาศาสตร์ที่หนาแน่น จำนวนชิ้นส่วนมากอาจมีต้นทุนสูง โดยเฉพาะเมื่อมีการ replicate หรือสร้างใหม่บ่อยครั้ง ควบคุมจำนวนตัวอย่างให้อยู่ในระดับเหมาะสมและวัดประสิทธิภาพใน Studio

ดู [visualizations/README.md](../../visualizations/README.md) สำหรับตัวอย่างและตัวเลือก renderer

## การวัดประสิทธิภาพ

ไดเรกทอรี `benchmarks/` มีสคริปต์ที่อิงกับ workload เพื่อศึกษาประสิทธิภาพของการดำเนินการทางคณิตศาสตร์ที่เลือกไว้

หัวข้อ benchmark ปัจจุบันประกอบด้วย:

- การคำนวณเมทริกซ์
- การหาค่าเหมาะที่สุดเชิงตัวเลข
- เรขาคณิตเชิงอนุพันธ์
- การประมาณค่าสถานะ
- ยูทิลิตี benchmark ที่ใช้ร่วมกัน

ผล benchmark อาจแตกต่างกันตามฮาร์ดแวร์ สภาพแวดล้อมขณะทำงาน มิติของอินพุต และรายละเอียดการติดตั้งใช้งาน

สคริปต์บางรายการต้องใช้ adapter เพื่อเชื่อม callback ของ workload เข้ากับ public API ที่ผ่านการตรวจสอบ การมีสคริปต์เหล่านี้ไม่ได้หมายความว่าได้ทำการวัดประสิทธิภาพอย่างครอบคลุมแล้ว

เอกสาร:

- [คู่มือการวัดประสิทธิภาพ](../../docs/BENCHMARKING.md)
- [สคริปต์ benchmark](../../benchmarks/README.md)

## พื้นฐานทางคณิตศาสตร์

VectorForge อาศัยศาสตร์ทางคณิตศาสตร์หลายแขนง

| สาขา | แนวคิด |
|---|---|
| พีชคณิตเชิงเส้น | การดำเนินการเมทริกซ์ การแยกตัวประกอบ ค่า eigenvalue |
| เรขาคณิตเชิงอนุพันธ์ | ความโค้ง ความบิด กรอบสัมผัสและกรอบปกติ |
| ทฤษฎี Lie | SO(3), SE(3), แผนที่เลขชี้กำลังและลอการิทึม |
| การวิเคราะห์เชิงตัวเลข | การประมาณค่า การอินทิเกรต ตัวแก้แบบวนซ้ำ |
| ทฤษฎีความน่าจะเป็น | การประมาณค่าแบบเบย์เซียนและความไม่แน่นอน |
| การหาค่าเหมาะที่สุด | การประมาณค่าแบบกำลังสองน้อยที่สุดและการลดค่าซ้ำ |
| การประมวลผลสัญญาณ | การวิเคราะห์โดเมนความถี่และการแปลงเชิงตัวเลข |

อ่านคำอธิบายเพิ่มเติมได้ที่ [MATHEMATICS.md](../../docs/MATHEMATICS.md)

ไดเรกทอรี `research/` มีบันทึกทางคณิตศาสตร์และเอกสารสำรวจประกอบ

หัวข้อปัจจุบันประกอบด้วย:

- คณิตศาสตร์ของ Lie group และการแปลงเชิงพื้นที่

- อัลกอริทึมและส่วนขยายทางคณิตศาสตร์ที่อาจพัฒนาในอนาคต

บันทึกเหล่านี้จัดเก็บข้อพิจารณาทางทฤษฎีและแนวทางที่เป็นไปได้ระหว่างการพัฒนา เป็นเอกสารประกอบ ไม่ใช่การตรวจสอบทางคณิตศาสตร์อย่างเป็นทางการ

## การทดสอบ

VectorForge มีสคริปต์ทดสอบ regression และการทดสอบแบบครอบคลุม ซึ่งครอบคลุมการดำเนินการสำคัญในโมดูลต่าง ๆ

ขอบเขตการทดสอบปัจจุบันประกอบด้วย:

- การดำเนินการ quaternion และการแปลงวัตถุแข็ง
- การคูณและการแยกตัวประกอบเมทริกซ์
- การแก้ระบบสมการเชิงเส้น
- การคำนวณ eigenvalue
- การหาค่าเหมาะที่สุดเชิงตัวเลข
- การดำเนินการของ Extended Kalman Filter
- การประเมินเส้นโค้งและคุณสมบัติเชิงอนุพันธ์
- การคำนวณความยาวส่วนโค้ง
- เงื่อนไขขอบเขตของวิถี
- การหาอนุพันธ์อัตโนมัติ
- พลศาสตร์วัตถุแข็งและการวางแผนวิถี

### การเรียกใช้การทดสอบ

1. ติดตั้งโมดูล VectorForge ใน `ReplicatedStorage/VectorForge`
2. วาง test runner ไว้ใน `ServerScriptService`
3. เริ่มเซสชัน Play ใน Roblox Studio
4. เปิดหน้าต่าง Output
5. ตรวจสอบผลการทดสอบ

ชุดทดสอบนี้เป็นพื้นฐานเริ่มต้นสำหรับ regression test แต่ไม่ใช่การตรวจสอบทางคณิตศาสตร์อย่างเป็นทางการ และไม่รับประกันเสถียรภาพเชิงตัวเลข

ดู [tests/README.md](../../tests/README.md)

## ข้อควรพิจารณาด้านประสิทธิภาพ

อัลกอริทึมเชิงตัวเลขอาจมีต้นทุนสูงขึ้นตามมิติของอินพุต จำนวนรอบการวนซ้ำ และความถี่ในการทำงาน

เมื่อใช้ VectorForge ให้พิจารณา:

- หลีกเลี่ยงการแยกตัวประกอบเมทริกซ์ที่ไม่จำเป็น
- ใช้ผลลัพธ์ที่คำนวณไว้ซ้ำเมื่ออินพุตไม่เปลี่ยนแปลง
- จำกัดการดำเนินการที่มีต้นทุนสูงภายในลูปที่ขึ้นกับเฟรม
- เลือกค่าความคลาดเคลื่อนของตัวแก้และจำนวนรอบสูงสุดที่เหมาะสม
- วิเคราะห์ประสิทธิภาพด้วย workload ที่เป็นตัวแทน
- แยกการคำนวณที่มีอำนาจตัดสินใจฝั่งเซิร์ฟเวอร์ออกจากการคำนวณเพื่อแสดงผลฝั่งไคลเอนต์เมื่อเหมาะสม

การติดตั้งใช้งานปัจจุบันยังไม่ได้ผ่านการวัด benchmark อย่างครอบคลุม

<summary><strong>VectorForge ใช้แทน Roblox Vector3 หรือ CFrame หรือไม่?</strong></summary>

ไม่ใช่ VectorForge สำรวจการดำเนินการทางคณิตศาสตร์ที่เกินกว่ายูทิลิตีเวกเตอร์และการแปลงทั่วไป API ที่มีใน Roblox ยังคงมีประโยชน์และเหมาะสมกับงานพัฒนาทั่วไปจำนวนมาก

</details>

<details>
<summary><strong>VectorForge พร้อมใช้งานจริงใน production แล้วหรือยัง?</strong></summary>

ยังไม่พร้อม นี่เป็นโครงการเชิงทดลอง API พฤติกรรมเชิงตัวเลข ประสิทธิภาพ และรายละเอียดการติดตั้งใช้งานอาจเปลี่ยนแปลงได้

</details>

<details>
<summary><strong>สามารถใช้แต่ละโมดูลแยกกันได้หรือไม่?</strong></summary>

ไลบรารีจัดเป็นโมดูลคณิตศาสตร์แยกจากกัน ซึ่งตั้งใจให้ทำงานอย่างอิสระเมื่อทำได้ โปรดดูเอกสาร API เพื่อทราบฟังก์ชันและ dependency ที่มีให้ใช้งาน

</details>

<details>
<summary><strong>โฟลเดอร์ simulations, datasets และ visualizations มีไว้ทำอะไร?</strong></summary>

โฟลเดอร์เหล่านี้อยู่ควบคู่กับไลบรารีหลัก `simulations/` มีแบบจำลองขนาดเล็กที่คำนวณตามช่วงเวลา `datasets/` เก็บข้อมูลอ้างอิงและอินพุตตัวอย่าง และ `visualizations/` มีตัวช่วย Roblox สำหรับแสดงผล ทั้งหมดเป็นเอกสารสนับสนุนและไม่เปลี่ยนวิธีติดตั้งโมดูลหลัก

</details>

<details>
<summary><strong>VectorForge มี benchmark ประสิทธิภาพหรือไม่?</strong></summary>

มีสคริปต์ benchmark สำหรับ workload บางประเภท สคริปต์บางรายการต้องใช้ adapter และยังไม่มีผล benchmark ที่ครอบคลุม

</details>

<details>
<summary><strong>สามารถดูตัวอย่างการใช้งานได้ที่ไหน?</strong></summary>

ดูไดเรกทอรี `examples/` และ [examples/README.md](../../examples/README.md) โฟลเดอร์ `simulations/` และ `visualizations/` ยังมีตัวอย่างเฉพาะหัวข้อด้วย

</details>

<details>
<summary><strong>สามารถร่วมพัฒนาได้หรือไม่?</strong></summary>

ยินดีรับข้อเสนอแนะทางเทคนิค รายงานข้อผิดพลาด ข้อเสนอแนะ และการมีส่วนร่วม โปรดอ่านแนวทางการมีส่วนร่วมก่อนส่งการเปลี่ยนแปลง

</details>

---


<details>
<summary><strong>โฟลเดอร์สาขาวิทยาศาสตร์เป็นส่วนหนึ่งของโมดูลหลักเดิมหรือไม่?</strong></summary>

โฟลเดอร์เหล่านี้เป็นชั้นส่วนขยายเชิงทดลองแยกต่างหากที่รากของคลังโครงการ โมดูลหลักเดิมทั้งแปดยังคงอยู่ภายใต้ `src/VectorForge/` ส่วนขยายสามารถพัฒนาและทดสอบแยกกันได้ โดยลงทะเบียน dependency ของโมดูลหลักที่เป็นตัวเลือกผ่าน `VectorForgeShared/CoreRegistry.lua`

</details>

<details>
<summary><strong>โมดูลส่วนขยายทางวิทยาศาสตร์ทั้งหมดเสร็จสมบูรณ์และผ่านการตรวจสอบแล้วหรือไม่?</strong></summary>

ไม่ใช่ ส่วนขยายเป็นโครงสร้างพื้นฐานเพื่อการวิจัย ต้องตรวจสอบสมมติฐานทางคณิตศาสตร์ หน่วย เงื่อนไขขอบเขต การลู่เข้า เสถียรภาพเชิงตัวเลข และความเข้ากันได้กับ API ของโมดูลหลักที่ใช้งานจริงในแต่ละโมดูลก่อนนำไปใช้จริง

</details>

## เอกสาร

ไดเรกทอรี `docs/` มีเอกสารอ้างอิงทางเทคนิคสำหรับ VectorForge

- [เอกสารอ้างอิง API](../../docs/API.md) — การดำเนินการและอินเทอร์เฟซโมดูลที่มีให้ใช้งาน
- [สถาปัตยกรรม](../../docs/ARCHITECTURE.md) — การจัดระเบียบและการออกแบบโมดูล
- [คณิตศาสตร์](../../docs/MATHEMATICS.md) — แนวคิดและพื้นฐานทางคณิตศาสตร์
- [การตรวจสอบเชิงตัวเลข](../../docs/NUMERICAL_VALIDATION.md) — ข้อควรพิจารณาในการตรวจสอบ
- [การวัดประสิทธิภาพ](../../docs/BENCHMARKING.md) — วิธีการและคำแนะนำในการ benchmark
- [การตัดสินใจด้านการออกแบบ](../../docs/DESIGN_DECISIONS.md) — ข้อพิจารณาด้านการออกแบบโครงการ
- [อภิธานศัพท์](../../docs/GLOSSARY.md) — คำศัพท์ทางคณิตศาสตร์และเทคนิค
- [การจำลอง](../../simulations/README.md) — แบบจำลองเชิงตัวเลขและรายละเอียดการอินทิเกรต
- [ชุดข้อมูล](../../datasets/README.md) — ค่าอ้างอิง หน่วย และข้อมูลตัวอย่าง
- [ภาพแสดงผล](../../visualizations/README.md) — ตัวช่วยแสดงฉากและวิธีใช้งาน

โฟลเดอร์ส่วนขยายทางวิทยาศาสตร์อธิบายจุดประสงค์ของโมดูลผ่านคำอธิบายในซอร์สและภาพรวมของคลังโครงการนี้ ควรเพิ่มเอกสาร API เฉพาะสาขาและรายงานการตรวจสอบเมื่อโมดูลได้รับการยืนยันแล้ว

## การมีส่วนร่วม

ยินดีรับการมีส่วนร่วม ข้อเสนอแนะทางเทคนิค รายงานข้อผิดพลาด และข้อเสนอแนะต่าง ๆ

หากพบปัญหา โปรดระบุ:

- โมดูลที่ได้รับผลกระทบ
- ตัวอย่างขั้นต่ำที่ทำให้เกิดปัญหาซ้ำได้
- พฤติกรรมทางคณิตศาสตร์ที่คาดหวัง
- พฤติกรรมที่สังเกตได้จริง
- ข้อผิดพลาดที่เกี่ยวข้องใน Roblox Studio Output

ดู [CONTRIBUTING.md](../../CONTRIBUTING.md) ก่อนส่ง pull request

## สถานะการพัฒนา

VectorForge ยังคงอยู่ในช่วงทดลองอย่างต่อเนื่อง แนวทางการพัฒนาในอนาคตที่เป็นไปได้ ได้แก่:

**การปรับปรุงเชิงตัวเลข**
- เพิ่มวิธีแยกตัวประกอบเมทริกซ์
- ปรับปรุงเสถียรภาพเชิงตัวเลข
- จัดการอินพุตที่เสื่อมสภาพได้ดีขึ้น
- เพิ่มตัวแก้ปัญหาแบบวนซ้ำ
- ปรับปรุงการวินิจฉัยการลู่เข้า

**การขยายทางคณิตศาสตร์**
- เพิ่มเทคนิคด้านความน่าจะเป็นและการประมาณค่า
- เพิ่มยูทิลิตีการแปลงเชิงเรขาคณิต
- วิธีการอินทิเกรตเชิงตัวเลข
- เพิ่มการดำเนินการเรขาคณิตเชิงอนุพันธ์

**ประสบการณ์นักพัฒนา**
- ขยายเอกสาร API
- เพิ่มตัวอย่างที่ใช้งานได้จริง
- เพิ่มการทดสอบอัตโนมัติ
- benchmark ประสิทธิภาพ
- ปรับปรุงการจัดการข้อผิดพลาดและการตรวจสอบ

นี่คือทิศทางการพัฒนา ไม่ใช่คำมั่นว่าจะเผยแพร่ตามกำหนดที่แน่นอน
